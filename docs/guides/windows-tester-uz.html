Tez boshlash

  1. ZIP’ni papkaga chiqaring va DevForge_0.1.0_x64-setup.exe faylini ishga tushiring.
  2. Sozlamalar → Til va hudud bo‘limidan o‘zbek tilini tanlang.
  3. Runtime’lar bo‘limida PHP, Node.js, Caddy va Composer’ni o‘rnating. Baza uchun PostgreSQL ham kerak.
  4. Loyihalar → Loyiha qo‘shish orqali tayyor Laravel loyihangizning sinov nusxasini tanlang. Birinchi sinovda HTTPS, Vite va navbat worker’ini o‘chiq qoldiring.
  5. Baza kerak bo‘lsa, Xizmatlar va loglar bo‘limida xizmat yarating va loyiha ichida Baza biriktirish tugmasini bosing.
  6. Bog‘liqliklarni loyiha Terminal oynasida tayyorlang. Keyin Ishga tushirish → Brauzerda ochish tugmalaridan foydalaning.
Sinov nusxasidan foydalaningDasturni administrator sifatida ochmang. Ilova mavjud loyihani import qiladi; yangi Laravel loyihasini avtomatik yaratmaydi. Tayyor sinov loyihasini jamoangizdan oling yoki mavjud loyihadan nusxa tayyorlang.

2. O‘rnatish

  1. ZIP ustida o‘ng tugma → Extract all / Barchasini chiqarish. Installer’ni ZIP ichidan emas, chiqarilgan papkadan oching.
  2. DevForge_0.1.0_x64-setup.exe faylini ikki marta bosing. Run as administrator tanlamang.
  3. Til tanlash oynasi chiqsa, Uzbek / O‘zbekni tanlang. O‘rnatishni odatiy sozlamalar bilan tugating.
  4. Standart o‘rnatish joyi: %LOCALAPPDATA%\DevForge. Bu foydalanuvchi uchun o‘rnatiladi.
  5. Start menyusidan DevForgeni oching. Dastlabki ochilish WebView2 tayyorlanishi sabab biroz uzoqroq bo‘lishi mumkin.

Visual C++ talabi chiqsa, Microsoft runtime’ini o‘rnatib, DevForge installer’ini qayta oching. Microsoft prerequisite o‘rnatuvchisi alohida UAC tasdig‘ini so‘rashi mumkin; DevForge ilovasining o‘zi oddiy foydalanuvchi rejimida ishlashi kerak.

3. Til va ko‘rinish

Chap menyudan Sozlamalarni oching. Interfeys inglizcha bo‘lsa Settings, ruscha bo‘lsa Настройки deb ko‘rinadi.

  • Til va hudud: o‘zbek, rus yoki ingliz tilini tanlang.
  • Ko‘rinish: Yorug‘, Qorong‘i yoki Tizimga mos.
  • Tanlov avtomatik saqlanadi. Ilovadan chiqib, qayta ochganda saqlanganini tekshiring.

Interfeys tili loyiha fayllari, log matnlari va loyiha nomlarini tarjima qilmaydi.

5. Laravel loyihasini qo‘shish

  1. Loyiha nusxasini, masalan, C:\DevForge-Test\atlas ichiga joylang.
  2. Loyihalar → Loyiha qo‘shishni bosing.
  3. Loyiha papkasida publicni emas, composer.json joylashgan ildiz papkani tanlang.
  4. Loyiha nomi, o‘rnatilgan PHP va Node.js versiyalarini kiriting.
  5. Domen: masalan, atlas.devforge.test. Kichik lotin harflari, raqam va defis ishlating; boshqa loyiha domeni bilan takrorlamang.
  6. Birinchi oddiy sinov uchun HTTPS, Vite dev server va Navbat worker’ini o‘chiring. Keyin ehtiyojga qarab yoqasiz.
  7. Loyihani qo‘shing. Import o‘zi composer install, migratsiya yoki loyiha skriptlarini bajarmaydi.

6. PostgreSQL bazasini ulash

  1. PostgreSQL server runtime’ini o‘rnating.
  2. Xizmatlar va loglar → Baza xizmatlarida versiyani tanlab Xizmat yaratishni bosing.
  3. Loyihalarga qayting va kerakli loyihani tanlang. Baza almashtirishdan oldin loyihani to‘xtating.
  4. Ma’lumotlar bazasi → Baza xizmati ro‘yxatidan xizmatni tanlab Baza biriktirishni bosing.
  5. Ulanishni tekshirish tugmasini bosing. «Bazaga ulanish muvaffaqiyatli» xabari kutiladi.

Har loyihaga alohida baza va login roli yaratiladi. Bir PostgreSQL xizmatini bir nechta loyiha ishlatishi mumkin. Parollar Windows credential saqlash tizimida turadi. Baza biriktirish loyiha .env faylini avtomatik qayta yozmaydi; DevForge boshqaradigan jarayonlarga ulanish muhiti beriladi.

Ixtiyoriy: .env fayliga baza sozlamalarini yozish

Bu qadam faqat sinov nusxasi uchun kerak bo‘lsa bajariladi. Loyihani to‘xtating. Quyidagi buyruqlarni oddiy PowerShellda bajaring. Boshqa o‘rnatish joyini tanlagan bo‘lsangiz, $df yo‘lini almashtiring.

$df = Join-Path $env:LOCALAPPDATA 'DevForge\devforge.exe'
& $df project list
$projectId = 'ROYXATDAGI_LOYIHA_ID'
& $df project env-plan $projectId
# Rejani tekshirgandan keyin:
& $df project env-apply $projectId

ROYXATDAGI_LOYIHA_ID o‘rniga ro‘yxatdagi haqiqiy idni yozing. env-apply o‘zgartirishni aniq bajaradi va zaxira nusxa qoldiradi. Tashqi DB URL eski bazani ko‘rsatib turgan holatda ham shu rejani ko‘rib chiqing. .env yoki parollarni xatolik hisobotiga qo‘shmang.

7. Terminal va Laravel tayyorlash

Loyiha ichidagi Terminal tugmasidan foydalaning. Windows’da CMD oynasi ochiladi; unda aynan shu loyiha uchun tanlangan vositalar ishlaydi. Oddiy tashqi terminaldagi global php va node boshqa bo‘lishi mumkin.

php -v
node --version
npm --version
composer --version

Yangi olingan, ishonchli Laravel sinov nusxasida bog‘liqliklar yo‘q bo‘lsa:

if not exist .env copy .env.example .env
composer install

.env.example bo‘lmasa, loyihaning o‘z sozlash tartibiga amal qiling. APP_KEY hali berilmagan yangi sinov loyihasida:

php artisan key:generate

Mavjud loyihaning ishlayotgan APP_KEY qiymatini qayta yaratmang. Keyingi buyruq bazani o‘zgartiradi; faqat alohida sinov bazasida, loyiha talabi bo‘yicha bajaring:

php artisan migrate

Vite kerak bo‘lsa, loyihada package.json va Vite sozlamasi bo‘lishi kerak. package-lock.json mavjud bo‘lsa npm ci, bo‘lmasa npm install bajaring. Shundan keyin ilovada Vite dev serverni yoqib Saqlashni bosing.

Navbat kerak bo‘lsa, loyihaning queue connection va jadval/xizmatlarini tayyorlab, Navbat worker’ini yoqing. Oddiy veb-sinovda uni o‘chiq qoldirish mumkin.

9. Domen va HTTPS

Birinchi sinovni HTTP’da bajaring. Maxsus hosts/CA ishonchi sozlanmagan holatda ilova, masalan, http://atlas.localhost:8080 kabi manzil ko‘rsatishi mumkin. Aynan ilova bergan manzilni oching; namuna portni majburan qo‘ymang.

.devforge.test domenlari va brauzer ishonadigan HTTPS uchun DevForge’ning hosts yozuvlari hamda lokal CA ishonchi alohida sozlanadi. Interfeysdagi HTTPS belgisining o‘zi Windows ishonchini o‘rnatmaydi. Dastlabki test uchun bu bosqich shart emas.

HTTPS’ni alohida tekshirmoqchi bo‘lsangiz
  1. Avval HTTP ishlashini tasdiqlang, so‘ng loyiha sozlamasida HTTPS’ni yoqib saqlang.
  2. Ishlab chiquvchi bilan CLI orqali CA va site system-plan rejalarini tayyorlang. Faqat DevForge’ga tegishli domen va sertifikat o‘zgarishini tekshiring.
  3. Tekshirilgan rejalar devforge-helper.exe apply <plan> <digest> bilan alohida administrator tasdig‘ida bajariladi. Asosiy ilova oddiy rejimda qoladi.
  4. Qayta ishga tushirib, ilova bergan HTTPS URL, sertifikat va Vite HMR’ni tekshiring.

Boshqa dasturlarning hosts yozuvlari yoki sertifikatlarini o‘chirmang. Sertifikat ogohlantirishini doimiy chetlab o‘tish HTTPS muvaffaqiyatli sozlanganini bildirmaydi.

11. DevForge’ni o‘chirish

  1. DevForge’dan to‘liq chiqing, uning CLI/terminal sessiyalarini yoping.
  2. Agar hosts yoki CA trust’ni o‘rnatmagan bo‘lsangiz, Windows Settings → Apps → Installed apps → DevForge → Uninstalldan foydalaning.
  3. Owned tizim yozuvlarini tozalash so‘ralsa, quyidagi preflight’ni bajaring yoki ishlab chiquvchiga xabar bering.
Cleanup preflight — oddiy PowerShell
$df = Join-Path $env:LOCALAPPDATA 'DevForge\devforge.exe'
& $df distribution check-uninstall
$planDir = Join-Path $env:USERPROFILE ('Desktop\DevForge-cleanup-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
& $df distribution cleanup-plan $planDir

Rejalar va digest’lar chiqariladi; bu buyruq tizimni o‘zgartirmaydi. Zarur bo‘lsa, ishlab chiquvchi bilan rejalarni tekshirib, helper orqali alohida administrator tasdig‘ida qo‘llang. So‘ng check-uninstall va Uninstall’ni takrorlang. Boshqa katalog tanlagan bo‘lsangiz $dfni moslang.

Uninstall loyiha kataloglari va baza ma’lumotlarini avtomatik o‘chirmaydi. Ilova ma’lumotlari odatda %APPDATA%\com.devforge.desktop ichida saqlanadi. Bu katalogni qo‘lda o‘chirish bazalarni yo‘qotishi mumkin; oddiy uninstall uchun uni tozalash shart emas.

Tester uchun tekshiruv ro‘yxati

Har bir holatda kutiladigan natijani tekshiring. Ikki loyiha sinovida turli PHP/Node versiyalarini loyiha talablariga mos tanlang.

Belgilash kataklari va quyidagi matn qayta ochilganda saqlanmaydi. Natijani hisobotga nusxalang yoki sahifani brauzer orqali PDF/chop etishga saqlang.

Xatolikni qanday yuborish kerak?

Diagnostika bo‘limidagi ilova/OS/arxitektura ma’lumoti, takrorlash qadamlari va kerakli log parchasi bilan yuboring. Holatni ko‘rsatadigan skrinshot foydali. Parol, token, shaxsiy ma’lumot yoki to‘liq .env faylini qo‘shmang.

Windows installer fayli

DevForge 0.1.0 — ichki sinov uchun. Avtomatik app update yoqilmagan. Native credential oynalari, minimum Windows 11 konfiguratsiyasi va ayrim tizim integratsiyalari bo‘yicha tester natijalari hali kerak.

Texnik build dalili: Windows native CI natijasi. Microsoft havolalari 12.11.2026 kuni rasmiy sahifalardan tekshirildi.
