Windows 10’da DevForge’ni sinash

Windows 10 22H2 x64 va Windows 11 x64 uchun ichki, imzolanmagan test paketi. Qo‘llanma internet bo‘lmasa ham ochiladi.

Sinov holati: Windows 10 kompyuteri yoki VM hozir mavjud emas. Build va avtomatik Windows tekshiruvlari Windows Server 2025’da bajariladi. Haqiqiy Windows 10’da o‘rnatish va runtime qabuli hali ochiq.

1. Talablar

  • Windows 10 22H2, build 19045 yoki yangiroq, Intel/AMD x64. Windows 11 ham qabul qilinadi. ARM va 32-bit bu paketga kirmaydi.
  • Microsoft Visual C++ v14 x64 Runtime. Visual Studio’ning o‘zi kerak emas.
  • WebView2 Evergreen Runtime. Yetishmasa installer yuklaydi.
  • Internet, bir necha GB bo‘sh disk joyi va alohida sinov loyihasi. Global PHP/Node o‘rnatish shart emas.

Win + R orqali winver ochib 22H2/19045 holatini tekshiring. Settings → System → About’da x64 tizim turini tekshiring.

2. Paketni tekshirish va o‘rnatish

  1. ZIP’ni foydalanuvchi yozishi mumkin bo‘lgan yangi papkaga chiqaring.
  2. PowerShell’da hashni tekshirib, paketdagi SHA256SUMS.txt bilan solishtiring:
Get-FileHash .\DevForge_0.1.0_x64-setup.exe -Algorithm SHA256

BUILD-INFO.json source commit, installer hash va haqiqiy sinov hostini ko‘rsatadi. Eski M6 installer Windows 10’ni rad etadi: aynan ushbu yangi paketdan foydalaning.

  1. DevForge_0.1.0_x64-setup.exe faylini oddiy foydalanuvchi sifatida oching. Ingliz, rus yoki o‘zbek tilini tanlang.
  2. Foydalanuvchingizga tegishli o‘rnatish katalogini tanlang. Ilovani administrator sifatida ishga tushirmang.
  3. VC Runtime yetishmasa rasmiy paketni o‘rnating va qayta urining. ARM/32-bit yoki build 19045’dan eski OS’da installer davom etmaydi.

Build Authenticode bilan imzolanmagan. Nashriyotchi va SHA-256’ni tekshiring; tashkilot siyosati bloklasa IT mas’uliga murojaat qiling.

3. Birinchi ishga tushirish

  1. Sozlamalarda rus, o‘zbek va ingliz tillarini almashtiring; qayta ochganda tanlov saqlanishini tekshiring.
  2. Runtime bo‘limidan PHP, Node.js, Composer va Caddy’ni o‘rnating. Loyiha talablariga mos versiyalarni tanlang.
  3. Sinov Laravel loyihasini qo‘shing yoki yaratish ustasidan foydalaning. Mavjud loyihalar boshlang‘ich ~/Devforge papkasidan ham aniqlanadi; loyiha papkasi Sozlamalarda o‘zgartiriladi.
  4. Avval SQLite va oddiy HTTP bilan ishga tushiring. So‘ng PostgreSQL/MySQL, queue, Vite va HTTPS’ni alohida sinang.
  5. Loyiha terminalida php -v, node --version va composer --version tanlangan versiyalarni ko‘rsatishini tekshiring.

Garnet/Redis xizmati boshqariladigan .NET runtime’dan foydalanadi. Microsoft’ning joriy Windows 10 support siyosati LTSC/Enterprise nashrlari bilan cheklangan. Home/Pro 22H2’da Garnet’ni vendor tomonidan qo‘llab-quvvatlangan deb hisoblamang; uning haqiqiy ishlashi ham alohida tekshirilishi kerak.

4. Windows 10 qabul ro‘yxati

SinovKutiladigan natija
22H2 x64’da o‘rnatishWindows 11 talabi bilan rad etmaydi; ilova ochiladi.
DiagnostikaQuyidagi buyruq os_supported: true, os_version: "19045" va vc_runtime: true qaytaradi.
Laravel va runtimePHP/Node tanlovi, SQL migration, HTTP/HTTPS, Vite, queue va mail ishlaydi.
Debug va worktreeBreakpoint ishlaydi; sinov worktree purge’i asosiy repo va readonly Git objectlarini saqlaydi.
Qayta o‘rnatish/o‘chirishLoyiha, baza va sozlamalar saqlanadi. Ilova ochiq paytda uninstall bloklanadi.

O‘rnatish papkasida oddiy PowerShell orqali:

.\devforge.exe distribution prerequisites
.\devforge.exe doctor

5. Xatolik hisoboti va o‘chirish

OS nashri, winver build’i, CPU turi, BUILD-INFO.json source commit’i, takrorlash qadamlari va xabarni yuboring. Parollar, tokenlar, .env, private key va haqiqiy bazani yubormang.

O‘chirishdan oldin tray menyusidan Chiqish amalini bajaring va DevForge terminal sessiyalarini yoping. HTTPS tizim yozuvlari bo‘lsa, devforge.exe distribution cleanup-plan YANGI_PAPKA orqali rejani yarating, ko‘rib chiqing va bundled helper bilan aniq tasdiqlangan rejani bajaring. Uninstaller loyiha va baza ma’lumotlarini saqlaydi.
