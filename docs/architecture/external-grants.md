# M13.1 external grant registry foundation

Status: isolated backend implementation; focused tests are pending. No public
CLI/MCP dispatcher, GUI consent flow, external client connection or native
credential-service behavior is established by this module.

## Decision

External clients must not reuse the all-powerful native desktop session/client.
`external_auth::ExternalRegistry` owns a private SQLite registry beneath the
manager's existing canonical `control` directory. Opening it requires the real
`Owner` and retains a private `OwnerGuard` sharing the existing singleton and
installer leases. SQLite/file handles close before that guard drops. Dropping
the original Owner cannot leave this registry mutating beside a replacement
manager; lease release occurs only at the final Arc, including any Workspace
permit. There is no Owner Drop unlock or second supervisor.

Issuance, bounded listing and durable revocation require a current native
`DesktopAuthority` for the same canonical owner root and OS user. Issuance and
revocation recheck proof expiry after SQLite waits and before commit. Tokens
and client/grant IDs are generated by the manager. A client name, role, root,
boolean confirmation or supplied token cannot create a grant.

The credential has 256 bits of randomness and is returned once at the trusted
issuance boundary. Its type has redacted Debug and no Clone/Serialize. Only its
SHA-256 digest is persisted; high entropy is essential to this hash-at-rest
choice. No plaintext credential, project path, mail/log/query body or source is
stored. A future consent/transport layer must deliver it privately without argv,
environment, logs, ordinary tool results or silent agent-config replacement.

## Policy

- Grants bind a fixed server client ID, project ID, canonical path digest and
  stable filesystem identity. Directory replacement or relocation requires fresh
  consent. Path-only identity fallback is rejected.
- Existing Observer, ProjectManage, ExecutionTest and SensitiveOperation rights
  remain independent. Observer covers safe metadata only. Separate internal
  LogContent, InspectorQueries, MailContent, SourceArtifacts and DatabaseQuery
  rights cover raw logs, SQL text, mail headers/body/links, source and querying.
  These additions are not yet public contract/schema exports or live tools.
- A database-query right is not a SQL sandbox, and management is not permission
  to execute project code. Future adapters still require constrained DB roles,
  project trust, execution grants, current review and resource guards.
- Grant lifetime is bounded to 30 days; at most 256 records are retained. Capacity
  fails closed. Owner-controlled pruning/rotation is a later policy, not silent
  eviction. Tokens/client IDs survive manager restart without native Keychain or
  Credential Manager startup access.
- The clock is server-owned. Durable high-water time and an expired flag prevent
  an observed expired credential from becoming valid after clock rollback or
  restart. Revocation is durable and immediately denies subsequent checks.
- Grants are not permanently frozen to a project revision. Reads can inspect
  current registered facts. Supplied expected revision is checked against the
  current trusted binding; mutation/review requirements remain separate.

Authorization returns a nonserializable point-in-time external identity, never
DesktopAuthority. A future dispatcher must revalidate at admission/dequeue and
define cancellation of running work. This foundation does not cancel accepted
running jobs automatically or provide an external actor submission route.

## Acceptance boundary

Eight focused fixture tests cover independent content/execution rights, stable
server identity and hash-only restart persistence, project/OS peer/filesystem
replacement and revision guards, expiry/revoke/clock rollback, bounded issuance,
desktop proof expiry during SQLite contention, unsafe ledger symlinks and registry
lease retention after Owner drop. They use isolated stores and in-memory desktop
authentication fixtures. Initial compilation encountered concurrent actor WIP and
local timestamp/helper errors; local errors were corrected. The integrator isolated the staged source from concurrent facade changes: all eight
fixture tests and scoped manager-library clippy passed on local macOS ARM64. No macOS/Windows native service, actual external
agent, production credential prompt or public grant enforcement is claimed.
